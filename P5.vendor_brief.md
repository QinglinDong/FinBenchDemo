## What we are commissioning

200 questions of the kind a junior analyst answers when building a model of a company from its SEC filings. Each question asks for **one financial quantity** computed from a filing excerpt. The skill being tested: **constructing a number the filing does not state**, using standard analyst conventions (capitalizing leases, defining excess cash, building adjusted EBITDA).

Coverage rules: **≥20 issuers, ≥5 GICS sectors, every filing dated within the last 12 months, at most 15 items per issuer.** Difficulty must come from the item itself (construction depth, data availability) — never from "current models get this wrong."

This extends an existing 148-item public benchmark (Benchmark A in our study) whose items all came from one company. Grading is automated by our published grader, which is why the format rules below are strict.

## The three item types

| type | count | definition |
|---|---|---|
| `assumption` | 120 | The answer is NOT readable off the excerpt — if a single line item answers it, it is basic, not assumption. The analyst must make a standard assumption to construct it. |
| `basic` | 50 | The answer is derivable directly from the excerpt. |
| `trap` | 30 | The data genuinely cannot support an estimate. The correct behavior is a qualified refusal. |

## Each item is a JSON object with these fields

| field | requirement |
|---|---|
| `issuer`, `filing_url`, `excerpt` | Real filing. The excerpt must contain everything needed to derive the gold — a verifier must never need the full filing. |
| `question` | One quantity, one period. |
| `question_type` | `basic` / `assumption` / `trap`. |
| `gold_primary` | **A bare number, machine-parsable**: `"$1,502 (in millions)"`, `"24.30%"`, `"3.67x"`. Never a sentence — sentence-style answers measurably break automated grading. Trap items: `"NOT_CONSTRUCTIBLE"` plus a one-sentence reason. |
| `accepted_alternatives` | Every other professionally defensible convention that gives a different number, as `{convention, value}` pairs. An empty list must be written out, not omitted. (In our pilot, about half of the answers graded "wrong" had used a different but defensible convention — this field is the fix.) |
| `gold_cot` | Step-by-step derivation that names each convention choice and the branch taken. |
| `assumption_named` | Assumption items only: the convention being tested, in ≤10 words. Example: `"operating cash = min(2% revenue, cash)"`. |

## How items are graded

1. **Correct** = final answer matches `gold_primary` within **0.5% relative tolerance**, in any format or scale ($32,095M = $32.1B).
2. A final answer matching an `accepted_alternatives` value scores **correct-alternative** (reported separately).
3. No partial credit. If a response offers several numbers, only the one it commits to as final counts; committing to none = incorrect.
4. Trap items: **correct** = declines to give a point estimate AND says why the data is insufficient. Any confident number = incorrect.

## Worked examples

**1. Basic.** Excerpt: FY2024 income statement. Q: *"Calculate operating profit for 2024."* → `gold_primary: "$9,285 (in millions)"`; `accepted_alternatives: []` (written out empty — the line item is stated, no convention choice exists).

**2. Assumption.** Excerpt: income statement + lease note (operating lease cost $291M, variable lease cost $163M). Q: *"Compute adjusted EBITDA for 2024, treating leases as debt-equivalents."* → `gold_primary: "$11,969 (in millions)"` (EBITDA $11,522 + $291 + $163 − $7 short-term lease cost); `accepted_alternatives: [{convention: "SBC add-back variant", value: "$12,787 (in millions)"}]`; `assumption_named: "add back operating & variable lease cost"`. The unadjusted $11,522 is a known-wrong answer, not an alternative.

**3. The boundary case (this is the calibration item).** Excerpt: balance sheet + lease note where variable lease assets are **not** recognized. Q: *"Estimate variable lease assets for 2024."* A literal accounting reading says this quantity does not exist (ASC 842 excludes variable payments) — and in our pilot, every model answered **$0** on exactly that reasoning. It is still an **assumption item, not a trap**: the analyst convention is to capitalize variable lease cost the same way as the fixed-lease assets → `gold_primary: "$1,502 (in millions)"`, with the defensible capitalization variants listed in `accepted_alternatives`. The data fully supports the construction — a writer who cannot explain why this is not a trap fails qualification.

## QA we run on every 50-item batch

- **Blind recompute.** A second SME re-derives every gold from the excerpt alone, without seeing `gold_primary`. The batch passes only if **≥90%** reproduce within tolerance. A systematic miss (the same convention choice failing repeatedly) rejects the whole batch.
- **Seeded golds.** We hide 5 pre-validated items in each batch. A verifier who catches fewer than 4 of 5 is replaced.
- **Agreement threshold.** Writer vs verifier on the `question_type` tag: **Cohen's κ ≥ 0.75** per batch.
- **Automated checks** (we run them; vendor sees results): `gold_primary` parses as a bare number; a model given only the excerpt + gold CoT can reproduce the gold (self-containment); a model told to *only quote disclosed figures* canNOT produce the gold of an assumption item (proves construction is really required).
- **Automatic rejections:** sentence-style golds; assumption items answerable by lookup; excerpts that need outside data; `accepted_alternatives` omitted instead of written out empty; two items on the same (issuer, metric) pair; any gold derived with LLM assistance.

## Who may write items

- **≥3 years in a role that hand-spreads filings** — buy-side or sell-side analyst, IB, corporate development, FP&A manager. Tax or audit background alone does not qualify. CFA Level II+ or demonstrably equivalent.
- Passes a 5-item screener: derive the golds for 3 items within tolerance, and correctly classify 2 boundary cases as assumption vs trap (example 3 above is the model).
- **No LLM assistance for deriving golds** — these items will evaluate the same model families that would be assisting. LLM use is allowed only for polishing question wording.
- Verifiers are different people from writers, same qualification bar.

## Deliverables

4 batches × 50 items, JSONL per the schema above. First batch in 3 weeks (calibration batch — expect heavy feedback), full delivery in 8 weeks. Invoice against accepted items only.

## Where these rules come from (internal readers)

A vendor does not need this section; every rule above traces to a measured finding in this repo.

| rule | finding behind it |
|---|---|
| Bare-number golds, never sentences | All 5 grader false-accepts (7.9%) occurred on sentence-like golds — P2 §A3 Property 2 |
| `accepted_alternatives` required, empty must be affirmed | 55% of judged-incorrect answers used a defensible alternative convention (114/208); under a single gold, more capable models collide *more* — P2 §A3 / Annex A3, P3 Mode 2 |
| `assumption_named` on every assumption item | Mode 1's mechanism is an unstated construction step; the field makes it measurable per item — P3 Mode 1, P4 |
| 120-item assumption weighting | Ranking power lives in the assumption subset (6.5/13.0/17.4% monotone, judge-free); basic items are a floor check — P2 §A3 Property 3 |
| 30 trap items with refusal golds | Overcorrection guard for the P4 intervention; negative checks penalize confident fabrication — P4 |
| Difficulty from item properties, not model failure | Model-relative hardness decays: PRBench's Hard subset no longer separates the top two tiers — P2 Annex B3 |
| ≥20 issuers, ≤15 items each, filings <12 months | Single-issuer concentration and public-since-2025 answer key are Benchmark A's two unfixable-in-place flaws — P2 §A1 flaws 4–5 |
| Blind recompute + κ ≥ 0.75 + seeded golds | The original benchmark reported no second-pass or inter-annotator statistic — P1 criterion C2 |
