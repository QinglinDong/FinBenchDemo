# One thing we chose not to do, and why

**We did not run the analyst-persona prompting probe** — re-running the 46 assumption items with a system prompt instructing the model to behave like a buy-side analyst and construct estimates with stated assumptions. It is the obvious next experiment, it costs about $30 and an afternoon, and it is Stage 0 of the P4 plan. We chose not to, twice over.

The principled reason is ordering: the probe measures an *intervention*, and an intervention delta is only interpretable on a *validated instrument*. The 24-hour budget went to the instrument — building the grader FinanceQA never shipped, and proving with three separate measurements (format-invariance probe, human adjudication with κ, tier separation) that its numbers mean something. Running the persona probe before the grader was validated would have produced a delta we couldn't defend; running it after validation was complete would have been fine, but by then the honest move was to pre-register it as P4's gating experiment rather than bolt an unregistered result onto P2 and be tempted to narrate whichever way it came out.

The practical reason is budget discipline: mid-project, the API budget owner asked that every inference run be approved in advance. The probe is specified precisely in `leverage_finding.md` (Stage 0) — prompt text, items, grader, and what each outcome would imply — so anyone with the repo can run it in one sitting.

Two smaller deliberate cuts, for completeness: (1) the Stage-1 grader fix for the measured ~8% false-accept channel is **quantified but not applied** (63 re-routed judge calls, ~$1.5) — documented in P2 instead, so the checked-in numbers remain exactly reproducible from the checked-in code; (2) PRBench-Finance got a full static teardown (data downloaded, rubric structure measured, discrepancies vs. its paper documented in P1) but no model runs — one deep, runnable improvement on FinanceQA beat two shallow ones inside the timebox.
